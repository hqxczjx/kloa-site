# 歌单列表重新设计 · 设计稿

- **日期**：2026-07-23
- **状态**：待用户审阅
- **涉及页面**：`/music`（`src/pages/music.astro` → `src/components/react/SongList.tsx`）
- **范围**：歌单列表的**视图层重构**（布局、筛选、排序、视觉编码、移动端）。**不改** `songs.json` 数据结构与 `collector/` 采集逻辑。

---

## 1. 背景与目标

歌单页是本站核心功能页，承担"快速找歌 + 一键点歌"的实用场景。当前实现是一个固定 600px 高的虚拟化纯文本列表，用户对展示效果不满意。本次重设计目标：

1. **提高一屏可读歌曲数与扫视效率**（418 首需要高密度 + 强信息层级）。
2. **让筛选/排序/搜索更好用**（现仅搜索 + 标签折叠，缺排序、缺高亮）。
3. **视觉上更贴站点的 Angel/Demon 双主题**（玻璃拟态、光晕、OKLCH）。
4. **保留并增强现有交互资产**（整行复制点歌、拼音搜索、虚拟滚动、toast）。

## 2. 现状与痛点

现状（`SongList.tsx`，287 行）：

- 固定 600px 高虚拟列表，单行 90px，左侧歌名+歌手、右侧标签+复制按钮。
- 支持：歌名/歌手/**拼音**搜索、标签折叠筛选（语言/流派/礼物合并）、空状态、复制 toast。
- 缺：排序、搜索高亮、随机、礼物曲视觉编码、移动端优化。

痛点：

- **一屏放不下几首**（90px 行高 + 600px 容器），密度低。
- **信息层级弱**：歌名/歌手/标签视觉重量接近，扫视时无主次。
- **标签挤在右侧**，行内布局松散。
- **礼物曲（SC 曲）无视觉标记**，13 首 SC 曲淹没在列表里。
- **无排序**，418 首只能按录入顺序浏览。

## 3. 调研依据

对 9 个 VTuber 歌单/歌回站与主流音乐曲库 UI 做了深读（Akegarasu/vup-song-list、雨纪 ameki、Hololive Official Music、HoloSetli、HoloIndex、Holo 3D LIVE、Utawaku Portal、にじさんじ歌唱まとめ、绯间樱斩）。可借鉴模式归纳：

| 模式 | 借鉴点 | 本设计如何采用 |
|---|---|---|
| 密集表格行（Akegarasu/ameki/にじさんじ） | 信息密度高、整行点击复制、视觉编码特殊曲 | 采用列对齐表格 + 整行复制 |
| 列头排序（HoloSetli/主流音乐 App） | 多维度排序、可预测 | 采用列头点击排序 |
| 分类筛选按钮组（Akegarasu） | 语言/标签按钮网格、选中高亮 | 采用语言 chip + 流派 chip |
| 随机发现（Akegarasu「随便听听」/Utawaku） | 降低选择门槛、直播场景实用 | 采用「随机一首」 |
| 搜索高亮（主流音乐 App） | 命中可视化 | 采用 `<mark>` 高亮 |
| 应避免：表格在移动端横向滚动；`includes` 大列表搜索；硬编码颜色；无空状态引导 | — | 采用移动端卡片回退、复用 pinyin-pro、CSS 变量、空状态引导 |

## 4. 设计方向

采用方向 **A · 玻璃乐谱**（信息密度优先），行布局采用 **列对齐表格（V3）**。

- **为什么是 A 而非卡片（B）/时间轴（C）**：418 首且无封面/无时长/无外链（数据仅文本元数据），卡片网格浪费空间、视觉空洞；时间轴叙事性强但点歌场景要的是效率。密集表格最适合"找歌+点歌"。
- **为什么是 V3 列对齐而非单行/双行**：列对齐让语言/歌名/歌手/流派各自成列、纵向对齐，扫视时眼睛沿列下移极快；且天然支持列头排序。单行密度最高但无对齐、不可排序；双行层次好但占空间。

## 5. 信息架构与布局

### 5.1 页面结构（自顶向下）

```
┌─ 标题栏  「🎵 歌单」  「共 N 首 / 结果 M 首」  [🎲 随机一首]
├─ 筛选栏（sticky，玻璃拟态）
│    搜索框 · [语言 chip 组] · [流派 chip 组（热门8 + 更多▾）] · [💎 仅 SC 曲]
├─ 表头行（列对齐，可点排序）
│    语言 │ 歌名 ▲▼ │ 歌手 ▲▼ │ 流派 │ SC
├─ 虚拟化表格主体（VirtualList）
│    [行]…[行]…[行]
└─ 空状态（无结果时）
```

### 5.2 列定义（CSS Grid 列模板）

`grid-template-columns: 语言(固定~52px) | 歌名(1.3fr) | 歌手(1.2fr) | 流派(~64px) | SC(~64px)`

- **语言**：彩色 chip（见 §11）。
- **歌名**：粗体，主信息；搜索命中时高亮（§6）。
- **歌手**：次级灰色文字。
- **流派**：小 tag，仅显示首个流派（多个流派时显示主流派 + `+N`）。
- **SC**：SC 徽章（§8）；无礼物则空。

### 5.3 行交互

- **整行点击 → 复制**「点歌 {歌名}」到剪贴板，sonner toast 反馈（沿用现有）。
- **悬浮**：行底叠加主题色淡层 + 内描边 + 主题色 glow（复用 `.glow` 思路）。
- **密度**：行高约 44–48px（远小于现状 90px），一屏可见 ~12–14 行。

### 5.4 虚拟化

- **复用** 现有 `VirtualList`（`src/components/react/VirtualList.tsx`），仅改子项渲染与估算行高。418 行必须虚拟化，不可全量 DOM。
- 列头为虚拟列表**之外**的固定表头（不随滚动），保证列标题常驻。

## 6. 筛选与搜索

### 6.1 搜索

- 输入框 placeholder「搜索歌名 / 歌手 / 拼音…」。
- 复用 `pinyin-pro` 做拼音匹配（歌名 + 歌手）。
- **搜索高亮**：命中的歌名/歌手片段用 `<mark>` 包裹，背景为主题色 35% 透明、圆角。高亮函数对歌名与歌手分别标注。

### 6.2 语言 chip 组

- 4 个 chip：`国语(192) / 日语(155) / 英语(50) / 粤语(4)`（数量取自实时统计）。
- 多选 toggle；选中时主题色描边/底色。
- **筛选语义**：多语言选中 = 任一命中（OR，跨语言）。

### 6.3 流派 chip 组

- 热门 8 个直出：`流行 / 影视 / 动画 / 二次元 / 摇滚 / R&B / 游戏 / 爵士`（按数量排序取前 8）。
- 其余 13 个收进 **「+13 ▾」气泡**（Popover，点击展开剩余流派 chip）。
- 多选 toggle，OR 语义。

### 6.4 仅 SC 曲开关

- 一个 toggle，开启后只保留 `gifts` 非空的歌（13 首）。

### 6.5 筛选组合逻辑

- 维度间 **AND**：搜索 ∧ 语言 ∧ 流派 ∧ 仅SC。
- 维度内 **OR**：同维度多选任一命中。
- 与现有排序（§7）叠加后喂给 `VirtualList`。

## 7. 排序

- **机制**：点击表头列切换该列排序；再点切换升/降序；列头显示 `▲▼` 指示当前列与方向（主题色）。
- **可排序列**：语言、歌名、歌手、流派。
- **排序键**：
  - 歌名/歌手：用 `pinyin-pro` 生成拼音排序键（中文歌名/歌手按拼音 A–Z）。
  - 语言/流派：按字面字符串（取首项）。
- **默认排序**：**原始录入顺序**（即 `songs.json` 数组顺序）——用户明确选择不把拼音字母序作为默认。任意列被点击前显示默认序。

> 排序在 `useMemo` 内完成，作用于"筛选后"的列表，结果再交给虚拟列表。

## 8. SC / 礼物曲视觉编码

数据：`gifts` 数组，当前值为 `"30 SC"` / `"100 SC"` 等；共 13 首有礼物。**金额是动态的**，渲染时取实际值，不写死档位。

### 8.1 行底

- 有礼物的行铺**极淡金色水洗**做"特殊行"标记：
  - Angel 浅色：`oklch(0.955 0.035 85)`
  - Demon 深色：`oklch(0.24 0.05 76 / 0.5)`
- 极低彩度，仅"略泛暖"，不与徽章争色。

### 8.2 SC 徽章（选中样式 B：主题色实心胶囊）

- **实心主题色胶囊 + 白字 + 宝石图标 + 金额**：
  - 背景 `var(--accent)`（Angel=粉、Demon=蓝），字 `#fff`，主题色阴影。
  - 内容：`◆ {金额} SC`，例如 `◆ 100 SC`、`◆ 30 SC`（实现时 `◆` 用 lucide-react 的 `Gem` 图标，不用 emoji 字符，保证矢量清晰）。
- **金额取值规则**：`scAmount = max(gifts.map(parseInt))`；徽章显示 `◆ {scAmount} SC`。多礼物取最大值；非数字礼物回退显示原字符串。绝大多数歌曲只有一个礼物。
- **为什么实心胶囊**：与极淡金行底**不同色相**（粉/蓝 vs 金），且实心高饱和，在浅/深两套主题下都明显跳出，解决"行底与徽章颜色太近"的问题。

> 备选（未采用，留作后续开关）：按 SC 数值动态调行底透明度（金额越大行底越深）。

## 9. 随机一首

- 标题栏右侧 `🎲` 按钮。
- 行为：从**当前筛选结果**中随机抽一首 → 滚动定位到该行（`scrollIntoView` / 虚拟列表 `scrollToIndex`）并高亮闪一下 → 自动复制「点歌 {歌名}」+ toast。
- 结果为空时按钮禁用并提示。

## 10. 复制交互

- 整行点击复制（沿用现有 `点歌 {歌名}` 文案与 sonner toast）。
- SC 曲**视觉标记 only**，复制文案不特殊化（不自动加 `￥` 前缀）——保持简单；如需"SC 曲复制加前缀"可作为后续开关。
- 点击 chip / 表头 / 徽章 / 随机按钮时 `stopPropagation`，不触发行复制。

## 11. 主题适配（Angel / Demon）

- 整表用 CSS 变量驱动，浅/深两套结构相同、只换变量（已在 `global.css` 的 `:root` / `:root.dark` 定义）。
- **语言 chip 着色（固定，不随主题翻转）**：
  - 国语、粤语 → 粉 `--color-pink-500`
  - 日语 → 蓝 `--color-blue-500`
  - 英语 → 中性灰
  - 理由：中文系=天使粉、日语=恶魔蓝，语义稳定。
- **SC 徽章**：用 `var(--accent)`，随主题翻转（粉↔蓝）——与用户确认的样式 B 一致。
- **悬浮光晕**：复用 `--glow-color`；行 hover 用 `color-mix` 叠加 accent 淡层 + 内描边。
- **玻璃**：筛选栏与表容器复用 `.glass`（`.glass-holy` / `.glass-abyssal`）。
- **可访问性**：沿用 `prefers-reduced-motion`（关掉光晕/定位动画）；OKLCH 保证对比度。

## 12. 移动端

- 断点（与现有 Tailwind 响应式一致，约 `< 640px` / `sm`）：表格列对齐在窄屏会拥挤，**自动切换为卡片行**：
  - 卡片内纵向堆叠：`[语言 chip] 歌名（粗） / 歌手（灰） / 流派 tag / SC 徽章`。
  - 筛选栏改为横向滚动 chip 条 + 折叠的"更多"。
- 桌面（≥ sm）保持列对齐表格。
- 通过同一份歌曲数据 + 两个行组件（`SongRow` 桌面 / `SongCard` 移动）实现，CSS 媒体查询控制显隐，或同组件内响应式 Grid。

## 13. 数据模型

- **不变**：`{ title, artist, languages[], genres[], gifts[] }`，来源 `src/data/songs.json`（418 首）。
- 派生统计（构建时或运行时 `useMemo` 一次）：语言计数、流派按数量降许、热门流派前 8。
- SC 金额解析见 §8.2。

## 14. 组件拆分

为可读性与可测性，将现 `SongList.tsx` 拆为：

| 组件 | 职责 | 依赖 |
|---|---|---|
| `SongList`（容器） | 持有 query/filter/sort 状态、`useMemo` 出 filtered+sorted 列表、组合以下子组件 | nanostores 或 useState |
| `FilterBar` | 搜索框、语言 chip 组、流派 chip 组、`GenrePopover`、SC toggle | — |
| `GenrePopover` | "+N ▾" 展开剩余流派 chip | — |
| `SortHeader` | 可点列头 + `▲▼` 指示 | — |
| `SongTable` | 固定表头 + `VirtualList` + 行渲染分发 | VirtualList |
| `SongRow`（桌面） | 列对齐行 + 复制 + 高亮 + SC 徽章 | ScBadge |
| `SongCard`（移动） | 卡片行 | ScBadge |
| `ScBadge` | `◆ {金额} SC` 实心胶囊，金额动态 | — |
| `RandomButton` | 随机抽歌 + 定位 + 复制 | — |
| `EmptyState` | 无结果引导 + 清除筛选 | — |
| util `highlightMatch` | 把命中片段包成 `<mark>` | pinyin-pro 匹配结果 |
| util `pinyinKey` / `scAmount` | 排序键 / SC 金额 | pinyin-pro |

## 15. 样式落点

- **复用**：`.glass` / `.glass-holy` / `.glass-abyssal` / `.glow` / `.song-item`（hover）/ 现有 OKLCH token / `--accent-primary` 等。
- **新增（`global.css` `@layer components`）**：
  - `.song-table`、`.song-thead`、`.song-row`（含 `:hover` / `.is-sc` / `.is-copied`）
  - `.lang-chip--pink|blue|gray`、`.genre-chip`、`.sc-badge`、`.sort-arrow`
  - 移动卡片 `.song-card` 与断点
- 颜色一律走 CSS 变量 / `@theme` token，**禁止硬编码**（调研明确为坑）。

## 16. 范围边界（不做）

- ❌ 不引入封面图、时长、音频播放、外部链接（数据里没有，不造占位）。
- ❌ 不改 `songs.json` 结构与 `collector/`。
- ❌ 不做多页面/详情页（本轮仅列表视图）。
- ❌ 不做收藏/个人歌单（无账号体系，YAGNI）。

## 17. 测试策略

- **单元（Vitest，`__tests__/unit/components/`）**：
  - `FilterBar`：语言/流派多选、SC toggle、搜索联动。

  - `highlightMatch`：命中分段正确、无命中原样返回。
  - `scAmount`：单值、多值取 max、非数字回退。
  - `ScBadge`：渲染金额、无礼物不渲染。
  - `SongRow`：点击复制文案、`stopPropagation`、SC 行 class。
  - `RandomButton`：空结果禁用、命中后复制。
  - 保留并更新现有 `SongList.test.tsx`（573 行）中仍适用的断言。
- **E2E（Playwright，`__tests__/e2e/music.spec.ts`）**：

## 18. 验收标准

1. 一屏可见歌曲数显著提升（行高 ~44–48px，桌面 ~12+ 行）。
2. 列头可排序，默认为原始顺序，`▲▼` 指示正确。
3. 搜索支持拼音且命中高亮。
4. 语言/流派 chip 多选筛选正确（维度 AND、维度内 OR）。
5. 13 首 SC 曲有淡金行底 + 主题色实心胶囊徽章（金额动态），徽章与行底可清晰区分。
6. 随机一首从当前结果抽取并复制。
7. Angel/Demon 两套主题下视觉一致、对比度达标。
8. 窄屏自动切换卡片行，无横向滚动。
9. 单元 + E2E 测试通过，覆盖率达标。
